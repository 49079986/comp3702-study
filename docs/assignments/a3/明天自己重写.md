# A3 独立重写路线

目标是能够从官方空白 starter 重写，并解释每一行更新做了什么。先在参考实现上运行，再把它关掉写自己的版本。

## 第一步 先追踪一次交互

从 `ql_train_episode` 开始，把以下值写在纸上：当前状态、合法动作、选中动作、返回的新状态、真实奖励、是否终止。`perform_action` 的返回值顺序是 `(next_state, reward, error_message)`。

当前代码把随机探索放在训练方法，把贪心选择放在 `*_select_action`。评估调用不能更新 Q 表或权重。训练从 `get_init_state()` 开始，后续调用接着上一步返回的状态。

## 第二步 手算并重写 QL 更新

参考代码中训练样本的目标值为：非终止时 `reward + gamma * max_next_Q`；到达成功或岩浆终止状态时只用 `reward`。最大值只在下一状态合法动作中计算。

例如，旧 Q 为 1，奖励为 -2，gamma 为 0.9，下一状态最大 Q 为 5，alpha 为 0.2：目标值为 2.5，新 Q 为 1.3。你应能自己重新计算，并解释为什么目标值和新 Q 不是同一个数。若下一状态终止，目标值改为 -2。

自己在 starter 中实现 `ql_initialise`、`ql_train_episode`、`ql_select_action`。不要先复制辅助函数。能完成 L1 后，再看参考实现如何组织重复代码。

## 第三步 跟踪特征向量

FQ 固定输出 21 个特征，名称在 `FEATURE_NAMES`。查看初始状态一个合法动作的向量，确认长度、元素类型和数值都合理。权重最初为 0，因此初始 Q 值也为 0。

地图距离是特征输入；BFS 只读地形，忽略隐藏成本和概率。最近目标在收集数量足够前是未收集水晶，足够后是发射点。方向特征查看前方一格；boost 额外查看两格与四格。地形风险特征记录岩浆、岩石和坑的位置。

所有原始特征统一做 L2 缩放。报告若描述特征，必须同时说明这个缩放；例如表中的 bias 是归一化前的常数，归一化后不一定等于 1。权重大小也需要结合实际特征尺度理解，不能只根据列名判断。

自己实现 `fq_get_features`，用 `verify_protocol.py` 核对长度与有限性。不要从环境私有参数中取概率、成本或惩罚。

## 第四步 手算并重写权重更新

先算当前 `Q = dot(weights, features)`，再计算样本目标值和 `TD_error = target - Q`，最后更新每个权重：`w_i += alpha * TD_error * feature_i`。

拿两个特征做练习：旧权重 `[0, 0]`，特征 `[1, 0.5]`，终止奖励 -2，alpha=0.1，更新后权重应为 `[-0.2, -0.1]`。这个小例子为手算方便省略向量归一化；真实参考实现使用归一化后的 21 维向量。

写完后检查：终止状态不继续 bootstrap；未知状态仍能提取同样长度的特征；评估选择的动作合法；评估前后权重相同。

## 第五步 自己跑一次实验

先跑协议检查，再跑一个关卡，然后运行三学习率实验。打开 CSV，手算其中连续 50 个 episode 的平均回报，与图上相应点对照。前 49 个点使用已有 episode 的平均值。

对 Q4，使用共同预算实验的数据。核对 summary 中 `learning_threshold`、训练预算和 `evaluation_reward_floor` 对两种算法相同。记录“达到阈值”的 episode 与步数；未达到则保留缺失值。

你自己的代码可能得到不同结果。保留全部运行记录，报告使用你实际运行得到的数据，不照抄示例数值。
